# agent_nirs — контекст для Claude Code

Учебный проект к НИРС про ИИ-агентов (МГТУ им. Баумана). Задача преподавателя:
показать в коде разницу между «LLM + инструменты (без харнесса)», «LLM + харнесс»,
«харнесс + локальные инструменты» и «харнесс + инструменты по MCP».

## Главное правило

Архитектура и комментарии должны соответствовать глоссарию терминов НИРС.
Определения процитированы в doc-комментариях пакетов (`internal/*/`), это
источник истины. При изменениях сверяйся с ними и не придумывай новые значения
терминов. Ключевые моменты глоссария:

- LLM без состояния и ничего не выполняет: вызов инструмента — только предложение.
- Харнесс крутит цикл агента, исполняет вызовы (локальные сам, MCP через
  MCP-клиент), хранит историю и память, управляет контекстом и решает,
  будет ли вызван инструмент. Модель о памяти не знает.
- Цикл агента: проверка запроса на валидность и безопасность (промпт-инъекции,
  превышение прав) один раз до цикла → сборка контекста → шаги до критериев
  завершения или лимитов.
- Шаг — вызов инструмента или финальный ответ. Лимиты — шаги, токены, время.
- Память и контекст не пересекаются: в контекст идут только релевантные данные.
- Skill: в контексте только название и описание, текст — по выбору модели (`load_skill`).
- MCP — HTTP + JSON-RPC 2.0; MCP-сервер сам выполняет вызовы.
- Системный промпт не меняется от задачи к задаче.

## Устройство

- `cmd/01..04_*` — четыре варианта, `cmd/mcp_mail_server` — MCP-сервер почты.
- `internal/harness` — харнесс и цикл агента; `internal/agentcontext` — контекст;
  `internal/llm` — клиент OpenAI-совместимого API (повторы при 429/5xx);
  `internal/mcp` — протокол, транспорт, клиент, сервер (написаны вручную);
  `internal/tools`, `internal/localtools`, `internal/memory`, `internal/skills`,
  `internal/prompt`, `internal/cli`.
- Только стандартная библиотека Go, внешних зависимостей нет (осознанное решение).
  Официальный MCP SDK упомянут в README как вариант для реального проекта.

## Как запускать и проверять

```bash
go vet ./... && go test ./...      # тесты: цикл агента, лимиты, права, контекст, MCP, LLM-клиент
go run ./cmd/03_harness_local_tools
go run ./cmd/mcp_mail_server       # для варианта 4, в отдельном терминале
```

Модель задаётся переменными `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`
(подробно — README и `.env.example`). Сейчас используется бесплатный OpenRouter
(`https://openrouter.ai/api/v1`, модель `nvidia/nemotron-3-super-120b-a12b:free`,
лимит 50 запросов в день). Код от провайдера не зависит: подходит любой
OpenAI-совместимый API с поддержкой tools (Ollama, Yandex AI Studio, OpenAI и др.).

## Соглашения

- Комментарии, логи, README и сообщения коммитов — на русском.
- Логи хода работы: `[LLM]`, `[харнесс]`, `[MCP-сервер]`, `[MCP-клиент]` в stderr.
- После изменений: `gofmt`, `go vet`, `go test ./...`; README держать в соответствии с кодом.

- Интерфейс `llm.Model`, чтобы подключать провайдеров со своим форматом API
