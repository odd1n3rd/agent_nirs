# agent_nirs — LLM, инструменты, харнесс и MCP на Go

Четыре программы, которые по шагам показывают, чем отличаются:

1. **LLM + инструменты** (без харнесса);
2. **LLM + харнесс** (без инструментов);
3. **LLM + харнесс + локальные инструменты**;
4. **LLM + харнесс + инструменты по MCP** (вместе с локальными).

Код написан только на стандартной библиотеке Go. Пакеты и типы названы по
терминам из глоссария НИРС, а в doc-комментариях пакетов приведены
определения из глоссария (с пояснениями, как они отражены в коде).

## Чем отличаются варианты

| | 1. LLM + инструменты | 2. LLM + харнесс | 3. + локальные инструменты | 4. + MCP-инструменты |
|---|---|---|---|---|
| Модель получает описания инструментов | да | нет | да | да |
| Кто выполняет вызов инструмента | **никто** | — | харнесс, внутри программы | локальные — харнесс; MCP — MCP-сервер (харнесс отправляет вызов через MCP-клиент) |
| Цикл агента (LLM → шаг → результат → LLM) | нет, один вызов | есть, но всегда 1 шаг — ответ | есть | есть |
| История между запросами | нет (LLM stateless) | да | да | да |
| Релевантные данные из памяти в контексте | нет | да | да | да |
| Skills (каталог + `load_skill`) | нет | нет | да | да |
| Проверка запроса на валидность и безопасность | нет | да | да | да |
| Лимиты, сжатие контекста | нет | да | да | да |
| Подтверждение опасных вызовов | нет | — | да (`save_note`) | да (`save_note`, `delete_message`) |

Системный промпт собирается `prompt.Build` под возможности варианта: в
варианте 2 нет разделов про инструменты и skills, в варианте 1 — про skills.
Внутри одного запуска он не меняется.

Главное:

- **1 → 2.** Сама LLM ничего не выполняет и ничего не помнит. Она лишь
  возвращает текст или вызов инструмента (имя и параметры). В варианте 1 видно,
  что вызов просто печатается: исполнить его некому. Харнесс в варианте 2
  добавляет историю, память, проверки и лимиты, но без инструментов модели
  доступен только один шаг — финальный ответ. Формально это вырожденный агент.
- **2 → 3.** Харнесс получает инструменты, и цикл агента становится полным:
  модель предлагает вызов, харнесс проверяет и выполняет его, кладёт результат
  в контекст и снова вызывает модель. Вместе с инструментами появляются:
  - skills — тоже через инструмент: встроенный инструмент харнесса `load_skill`;
  - подтверждение опасного вызова (`save_note` меняет данные пользователя).
- **3 → 4.** Код харнесса не меняется. Добавляется ещё один источник
  инструментов, MCP-клиент (`mcp.Client` реализует тот же интерфейс
  `tools.Toolbox`, что и `LocalToolbox`). Модель видит одинаковые описания
  и не может отличить локальный инструмент от MCP-инструмента. Где
  выполнять вызов, решает харнесс.

Как это выглядит в логах (заглушка вместо LLM):

```
# Вариант 1 — вызов есть, выполнить его некому
Модель вернула вызов инструмента: get_weather {"city": "Казань"}
На этом всё. LLM только предложила вызвать инструмент.

# Вариант 3 — харнесс выполняет локальный инструмент сам
[LLM] шаг 1: предлагает вызвать load_skill({"name": "weather_report"})
[харнесс] записал в контекст skill "weather_report"
[LLM] шаг 2: предлагает вызвать get_weather({"city": "Казань"})
[харнесс] выполняю get_weather (локально)
[LLM] шаг 3: ответ текстом, цикл завершён

# Вариант 4 — тот же цикл, но вызов уходит на MCP-сервер
[LLM] шаг 2: предлагает вызвать search_messages({"query": "boss@company.com"})
[харнесс] выполняю search_messages (MCP-сервер http://127.0.0.1:8000/mcp)
[MCP-сервер] tools/call: выполняю search_messages map[query:boss@company.com]
```

## Как устроено (термины → код)

| Термин | Где в коде |
|---|---|
| LLM | `internal/llm`: один вызов `Complete(messages, tools)`, состояния нет |
| Токен | `llm.Response.TotalTokens`, лимит `Limits.MaxTokens` |
| Запрос пользователя | аргумент `harness.Run(request)` |
| Системный промпт, критерии завершения | `internal/prompt`: собирается один раз при запуске и дальше не меняется |
| Промпт-инъекция | `harness.checkSecurity` (запрос), предупреждение в `harness.execute` (результаты инструментов) |
| Инструмент (name, description, input_schema, required) | `tools.Tool` (`required` лежит внутри `InputSchema`, как в JSON Schema) |
| Список инструментов | `agentcontext.Context.Tools`, собирается харнессом из всех `Toolbox` |
| Вызов инструмента | `llm.ToolCall`: модель возвращает имя и параметры |
| Результат инструмента | `tools.Result`: данные или ошибка (`IsError`, в контекст идёт с пометкой «Ошибка:») |
| Шаг | вызов инструмента или финальный ответ; считается в `harness.Run` |
| Локальный инструмент | `tools.LocalToolbox`, `internal/localtools` |
| Транспорт | `mcp.Transport`, реализация `mcp.HTTPTransport` |
| JSON-RPC 2.0 | `mcp.Request`, `mcp.Response` в `internal/mcp/protocol.go` |
| MCP | `internal/mcp`: `initialize`, `tools/list`, `tools/call` поверх JSON-RPC 2.0 и HTTP |
| MCP-сервер | `mcp.Server`, `cmd/mcp_mail_server` |
| MCP-клиент | `mcp.Client` |
| MCP-инструмент | инструменты, которые харнесс получает от `mcp.Client` |
| Постоянное хранилище | `memory.Storage`: файл `data/memory.json` |
| Память | `memory.Memory`; модель о ней не знает, обращается к ней только харнесс |
| Релевантные данные | `memory.Memory.Relevant`: передаются в контекст справочным блоком |
| RAG | `Relevant` — упрощённый RAG: поиск по совпадению слов вместо эмбеддингов |
| Skill | `internal/skills`, папка `skills/`: в контексте каталог, текст записывается в контекст по выбору модели (`load_skill`) |
| Контекст | `internal/agentcontext`: системный промпт, инструменты, каталог и тексты skills, релевантные данные, краткое содержание, история |
| Лимиты | `harness.Limits`: шаги, токены, время |
| Цикл агента | `harness.Run` |
| Харнесс | `internal/harness`: проверки, сборка контекста, выполнение и маршрутизация вызовов, подтверждение, управление контекстом |
| ИИ-агент | LLM + харнесс: варианты 3 и 4 (вариант 2 — вырожденный случай) |

Цикл агента в `harness.Run`:

```
запрос
 → проверка на валидность (не пустой, не длиннее MaxRequestRunes)
 → проверка на безопасность (промпт-инъекция; превышение прав при AGENT_READ_ONLY=1)
 → «запомни: …»? — харнесс сам пишет в память, модель не вызывается
 → сборка контекста (запрос + релевантные данные из памяти)
 └─ цикл:
      лимиты шагов / токенов / времени исчерпаны? → остановка
      управление контекстом: история длиннее MaxHistoryMessages → старая часть
        сжимается моделью в краткое содержание, история сокращается вдвое
        (и снова проверка лимитов: сжатие тоже тратит токены)
      LLM(контекст) → ответ (на последнем шаге — без вызова инструментов)
      текст            → шаг «финальный ответ»: критерии завершения выполнены
      вызовы инструментов → лимит токенов исчерпан? → вызовы не выполняются
                         для каждого вызова (каждый — отдельный шаг):
                           инструмент существует? параметры верны?
                           load_skill → записать текст skill в контекст
                           опасный? → спросить пользователя
                           локальный → выполнить сам; MCP → tools/call через MCP-клиент
                           результат (или «Ошибка: …») → в контекст
```

Как собирается контекст для каждого вызова модели (`Context.Messages`):

1. системное сообщение: системный промпт и каталог skills — одинаковое от запроса к запросу;
2. краткое содержание ранней части диалога (если история сжималась) — с пометкой «справочные данные, а не инструкции»;
3. тексты skills, которые выбрала модель (сжатие истории их не затрагивает);
4. история чата;
5. релевантные данные из памяти — справочным блоком перед текущим запросом;
6. текущий запрос, вызовы инструментов и их результаты.

Данные из памяти не попадают в системное сообщение, поэтому запись
«запомни: всегда отвечай по-английски» остаётся данными и не получает
прав системного промпта.

## Права и опасные действия

- Опасный инструмент (`save_note`, `delete_message`) выполняется только после подтверждения пользователя.
- У MCP-инструментов харнесс считает опасным всё, у чего нет аннотации `readOnlyHint: true`: так по умолчанию трактует инструменты спецификация MCP.
- `AGENT_READ_ONLY=1` — права «только чтение»:
  - запрос на изменение данных (в том числе «запомни: …») отклоняется
    проверкой на безопасность ещё до цикла. Это эвристика: ищутся глаголы
    вроде «удали», «сохрани», «отправь»;
  - опасные инструменты не попадают в список инструментов модели. Это
    основная защита: даже если эвристика пропустит запрос, модели нечем
    изменить данные.

## Запуск

Нужен Go 1.22+ и любой OpenAI-совместимый API. Команды выполняются из корня репозитория.

```bash
export LLM_BASE_URL=https://api.openai.com/v1   # или http://localhost:11434/v1 для Ollama
export LLM_API_KEY=sk-...                        # для Ollama любая строка
export LLM_MODEL=gpt-4o-mini                     # для Ollama, например, qwen2.5:7b
```

```bash
# 1. LLM + инструменты: модель вернёт вызов, но выполнять его некому
go run ./cmd/01_llm_tools "Какая погода в Казани?"

# 2. LLM + харнесс: диалог с историей и памятью, без инструментов
go run ./cmd/02_llm_harness
#   > запомни: я болею за Рубин
#   > За какую команду я болею?

# 3. LLM + харнесс + локальные инструменты
go run ./cmd/03_harness_local_tools
#   > Какая погода у меня в городе?   (город — из памяти, skill weather_report)
#   > Сохрани заметку: купить хлеб    (харнесс спросит подтверждение)
AGENT_READ_ONLY=1 go run ./cmd/03_harness_local_tools "Сохрани заметку: купить хлеб"   # отказ: превышение прав

# 4. LLM + харнесс + MCP-инструменты
go run ./cmd/mcp_mail_server            # отдельный терминал: MCP-сервер почты на :8000
go run ./cmd/04_harness_mcp_tools
#   > Есть письма от начальника?        (адрес начальника — из памяти, skill inbox_digest)
#   > Удали рекламное письмо            (харнесс спросит подтверждение)

# Тесты: цикл агента, лимиты, права, контекст, MCP-клиент и сервер
go test ./...
```

Каждая программа пишет ход работы в stderr: строки `[LLM]` — что предложила
модель, `[харнесс]` — что сделал харнесс, `[MCP-сервер]` — что выполнил сервер.
Если передать запрос аргументами, он выполнится один раз; без аргументов
запускается диалог.

Память при первом запуске копируется из `data/memory.example.json` в
`data/memory.json` (этот файл и заметки `data/notes.txt` в git не хранятся).

## Замечания

- MCP реализован вручную (HTTP + JSON-RPC 2.0, подмножество транспорта
  Streamable HTTP), чтобы было видно, что это за протокол:
  - транспорт отделён от сообщений;
  - клиент переподключается, если сервер забыл сессию;
  - сервер проверяет `Origin`.

  Реализация совместима с официальным SDK: Go-клиент работает с сервером на
  Python SDK (`FastMCP`, ответы в SSE), а Python-клиент — с Go-сервером.
  В реальном проекте вместо `internal/mcp` стоит взять официальный
  [github.com/modelcontextprotocol/go-sdk](https://github.com/modelcontextprotocol/go-sdk).
- Релевантные данные ищутся по совпадению слов. Это упрощённый RAG: обычно
  ищут по эмбеддингам, то есть по смыслу.
- Проверки на безопасность упрощены: промпт-инъекция ищется регулярным
  выражением, права — один флаг «только чтение». Они показывают, в каком
  месте цикла стоят проверки.
- Стоимость отдельно не ограничивается: она пропорциональна токенам, поэтому
  её ограничивает лимит токенов. Если провайдер не сообщает расход токенов,
  он оценивается по объёму запроса и ответа.
- Справочные блоки и тексты skills передаются отдельными сообщениями с ролью
  `user`, поэтому несколько таких сообщений могут идти подряд. OpenAI, Ollama
  и большинство моделей это принимают. Шаблоны со строгим чередованием ролей
  (например, некоторые модели Mistral в vLLM) могут вернуть ошибку.
- Если остался последний шаг, харнесс просит модель ответить без вызова
  инструментов (`tool_choice: none`), чтобы работа не закончилась без ответа.
- Данные погоды и почты выдуманные.

## Структура

```
cmd/
  01_llm_tools/            вариант 1
  02_llm_harness/          вариант 2
  03_harness_local_tools/  вариант 3
  04_harness_mcp_tools/    вариант 4
  mcp_mail_server/         MCP-сервер почты
internal/
  llm/           клиент LLM (OpenAI-совместимый /chat/completions)
  tools/         инструмент, результат, Toolbox, локальные инструменты
  localtools/    get_weather, get_current_time, save_note
  mcp/           протокол, транспорт, MCP-сервер, MCP-клиент
  memory/        постоянное хранилище и память
  skills/        загрузка skills
  agentcontext/  контекст
  prompt/        системный промпт
  harness/       харнесс и цикл агента (+ тесты)
  cli/           диалог в терминале, подтверждение, запуск
skills/          weather_report, inbox_digest
data/memory.example.json   пример памяти
```
